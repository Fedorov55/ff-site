# Design Audit — F&F Site

## 1. Текущее состояние
- 157 HTML-страниц, 2 CSS-файла (`css/style.css` ~123 KB, `css/critical.css` ~27 KB).
- Инлайн-стилей: **2212** (`style="..."`) — основной источник «разрозненности».
- FAQ: поддерживаются оба набора классов (`faq__q`/`faq__question`, `faq__a`/`faq__answer`) — дублирует CSS.
- Хедер/футер структурно одинаковы, но пути относительные (root vs подпапки) — визуально ок.
- Много «странных» блоков с inline-стилями (CTA, карточки, таблицы) без общих компонентов.

## 2. Основные проблемы
1. **Нет единой дизайн-системы**: цвета/отступы/радиусы задаются прямо в HTML и разбросаны по CSS.
2. **Дублирование CSS**: одни и те же компоненты (`.service-card`, `.case-card`, `.faq__item`) описаны несколько раз с разными значениями.
3. **Инлайн-стили**: 2212 вхождений — затрудняют поддержку и единообразие.
4. **Типографика**: разные размеры/веса для одинаковых элементов (заголовки, карточки).
5. **Контент**: на гео-страницах и кейсах мало текста, нет структуры «проблема → решение → результат».
6. **Изображения**: мало реальных скриншотов/схем, много текстовых блоков без визуала.

## 3. План Фазы 1 (дизайн-система)
1. Создать `css/tokens.css` с переменными:
   - Цвета: `--bg`, `--card`, `--text`, `--gold`, `--neon`, `--border`, `--muted`.
   - Типографика: `--font-sans`, `--font-mono`, размеры `--text-xs..--text-4xl`.
   - Spacing: `--sp-1..--sp-8`, radius `--radius-sm/md/lg`, shadows.
2. Выделить компоненты в `css/components.css`:
   - `.header`, `.footer`, `.hero`, `.card`, `.faq`, `.cta`, `.breadcrumbs`.
3. Удалить дублирующиеся правила из `style.css`/`critical.css`.
4. Создать эталонную страницу (`services.html`) с новой системой.
5. Подключить токены на 5–10 ключевых страницах и проверить Lighthouse.

## 4. Следующие шаги
- Утвердить палитру и типографику (предлагаю сохранить текущую: тёмный фон `#0A0D14`, золото `#D4AF37`, неон `#00FF88`).
- Начать с токенов и компонентов, затем массово заменять инлайн-стили.
- Параллельно собирать контент для гео/кейсов (Фаза 3).
