CTA-хаос («кнопки-сироты») На одной странице повторяется: «Получить точную смету» «Получить консультацию за 15 минут» «Посчитать стоимость» «Получить расчёт» «Позвонить» «Получить смету» Часто  2–4 одинаковых CTA подряд  без привязки к блоку. На index между секциями всплывают мини-блоки только с двумя кнопками «Получить расчёт / Позвонить» (textLen ≈ 41). Правило:  1 primary + максимум 1 secondary на смысловой блок. В конце страницы — один финальный CTA-блок. 2.3. Canonical и домен На главной: canonical → https://ff-it.ru/ Сайт   открыт   на  fedorov55.github.io/ff-site/ Пока GitHub Pages — зеркало, это допустимо, но: все внутренние ссылки должны быть согласованы; OG/canonical не должны путать поисковик, если github.io тоже индексируется. 2.4. Кнопки без доступного имени На index:  16  button / a.btn без текста и без aria-label (иконки, слайдеры, закрытие и т.п.). 2.5. Blog Страница живая по HTTP, но структурно слабая: мало/пустые заголовки в выдаче, карточки постов неочевидны. Риск «пустой» выдачи для пользователя. 2.6. Team Заголовки есть (истории), но  нет явных карточек людей с именами/ролями  в привычном виде (Булат, Эмиль, Диляра, Руслан). «Команда» читается как лонгрид, а не как trust-блок. 3. Страницы — поштучный разбор index.html Плюсы:  сильный hero, терминал, brandbar с цифрами, JSON-LD, один H1, meta description нормальная. Минусы: куча пустых  section.reveal ; повторяющиеся CTA-блоки «Получить расчёт / Позвонить»; одни и те же 3 буллета (15 мин / бэкап / без заложников) на всей странице; длинная простыня без жёсткой иерархии «проблема → решение → цена → кейс → FAQ → CTA». support.html Плюсы:  понятный intro, тема абонентки. Минусы:  калькулятор нужно явно якорить и не дублировать CTA; много пересечения текста с главной. servers.html Плюсы:  H1 и первые 2–3 блока осмысленные. Минусы:   критично много пустых секций ; формы на странице нет; CTA снова набор синонимов. cases.html Плюсы:  реальные кейсы, картинки с alt, ссылки на cases/*.html (200 OK). Минусы:  «cards: 71» — похоже на переразметку (лишние обёртки); CTA в intro можно сократить до одной primary. blog.html Проблема:  слабая сетка материалов / пустые заголовки в структуре. Нужна нормальная лента: тег, дата, lead, ссылка. about.html Плюсы:  принципы 01–05, хронология, цифры. Минусы:  title дублирует «Казань | F&amp;F» странно; мало «официальности» (реквизиты, договор одним кликом — кнопка есть, проверить файл). team.html Минусы:  нет классических карточек команды; trust-эффект слабее, чем мог бы быть. contacts.html Нужна рабочая форма (action/backend или хотя бы mailto / Telegram). Без обработки заявок весь сайт — витрина без кассы. services / infrastructure / security / audit / vpn / for-* Все отдают 200. Риск тот же: шаблонные intro + одни и те же CTA + пересекающийся текст. legal (privacy, terms, cookie) 200 OK —  хорошо .  Проверить актуальность формулировок под 152-ФЗ и cookie. 4. Дублирование контента и конфликт canonical - **Проблема**: На всех страницах GitHub Pages указан `&lt;link rel="canonical" href="https://ff-it.ru/"&gt;` и `og:url` на `ff-it.ru`. При этом страницы доступны по адресам `fedorov55.github.io/ff-site/*.html` и индексируются (robots.txt разрешает `Allow: /`). Это создаёт дублированный контент: поисковики видят две копии сайта, но canonical указывает на другой домен. GitHub Pages может выпасть из индекса или, наоборот, создать конкуренцию основному домену. - **Рекомендация**: Определить, какой домен основной. Если `ff-it.ru` — то на GitHub Pages нужно поставить `&lt;meta name="robots" content="noindex, nofollow"&gt;` и закрыть сайт в robots.txt, либо настроить 301-редирект (на GitHub Pages это невозможно, поэтому только noindex). Если  GitHub Pages — тестовая среда, её не нужно индексировать. Если же GitHub Pages — самостоятельный сайт, canonical и og:url должны указывать на `fedorov55.github.io/ff-site/`. ### 2. Отсутствие sitemap.xml на GitHub Pages - **Проблема**: `robots.txt` ссылается на `https://ff-it.ru/sitemap.xml`, но на GitHub Pages файла `sitemap.xml` нет (ошибка 404). Поисковые роботы не получают карту сайта для GitHub Pages. - **Рекомендация**: Сгенерировать `sitemap.xml` для GitHub Pages (список всех страниц) и указать его в robots.txt, либо полностью закрыть GitHub Pages от индексации, если это тестовая копия. ### 3. Несоответствие внутренних ссылок - **Проблема**: В навигации и на главной странице часть ссылок ведёт на относительные страницы GitHub Pages (`support.html`, `servers.html`, `services.html`), а часть — на абсолютные URL `ff-it.ru` (например, в блоке «Что ломается в субботу»: `https://ff-it.ru/support.html`). Пользователь может переходить между разными доменами непреднамеренно. Кроме того, некоторые страницы на GitHub Pages существуют (`support.html`, `services.html`), но ссылки ведут на `ff-it.ru`, где эти же страницы могут быть недоступны (например, `ff-it.ru/support.html` вернул ошибку при проверке). - **Рекомендация**: Привести все внутренние ссылки к одному домену. Если GitHub Pages — тестовая копия, ссылки не должны вести на продакшн-домен. Если продакшн — `ff-it.ru`, то GitHub Pages не должен иметь своей навигации, ведущей на относительные пути. ### 4.
